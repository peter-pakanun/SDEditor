# Explicit Use English decisions

This first slice supports ordinary **PoE2 text fields** in shared and private local workbooks. It deliberately excludes grammatical/class/named forms, Gender enum fields, DNT fields, absent/marker-only English and PoE1. The toolbar shows a disabled Eng control with an explanatory tooltip for those exclusions. Legal blank saves do not establish runtime fallback semantics for those excluded fields. Ordinary identical-English translations remain fully allowed.

Separately, the owner-confirmed inherent English fallback for blank PoE2 `NPCTalkDialogueTextAudio` class variants (also in its `_Gender` worksheet) has a **Use English** display cue and English preview. **Review blank variants** stages ordinary per-field source reviews until Save, preserving exact targets and individual populated-variant review. This narrow workflow does not create explicit `englishIntent` decisions or broaden the Eng toggle to other forms; required Missing flags retain their existing meaning. See the [Editor Guide](editor_guide.md) for its controls.

The formatting toolbar places **Eng** immediately after Underline and a separator. New activation is enabled only when the current editor draft is blank (including whitespace only) or exactly equals the raw English source. A different nonempty draft disables activation with an explanatory shared Tooltip; equality does not trim, fold case, normalize Unicode/newlines or use the source fingerprint. Existing approvals remain removable even after typing a different draft, subject to the existing operational/context guards. The button has the accessible name **Use English**, a purpose/action tooltip, native Tab/Enter/Space behavior and the same active styling as formatting buttons. Set saves the whole ID with that field blank, records source-bound intent/review and preserves committed-before plus previous editor text in history. Activate an active Eng to require translation again. Ineligible controls explain their limitation in the tooltip; an old unsupported decision can still be removed. Ordinary identical-English/blank saves and draft typing never infer approval. There is no verbose note below the toolbar.

Approved fields display the dimmed placeholder `-- Use English --` in their translation block, including collapsed rows. Their translation preview renders the actual English source through the normal renderer, while a nonempty draft still previews its own text. The cue is presentation only: saved/exported targets stay blank and the placeholder never becomes translation text. Invalid, revoked, stale or conflicted decisions do not get this display. See [placeholder and preview validation](clienttext_english_presentation.md).

A valid active decision resolves the normal Missing counter, Missing filter, field and row indicators, sheet color aggregation, attention navigation, actionable diagnostics and assigned progress. Raw target emptiness remains an internal field fact; it creates no competing visible counter or warning. Completed consistency scans retain the approved field's source/form peer membership while suppressing findings for its blank target, so later ordinary saves and shared edits refresh the record and its peers without a full rescan or clearing unrelated findings. Source mismatch, suspension, revocation, ineligibility or genuine conflict cannot resolve Missing. Missing-only work now stays in the initial workload denominator until translated or explicitly resolved. Metadata-only approval still preserves `saved:false`; it does not manufacture authored Saved work.

The existing color order remains red, orange, purple, green, grey, no color. Completing originally Missing work uses grey; source-reviewed work and eligible authored corrections retain their established colors. Unchanged complete originals remain uncolored. Targets still export blank, and original raw text, formatting structure, filenames, workbook identities and macro bytes remain under the existing export contract. Status cell/tab colors reflect resolved intent using the existing palette. No old blank is retroactively approved as an explicit Eng decision; text-field Eng actions remain per field.


## Identity and lifecycle

The existing game/branch/logical-group/language ancestry, group/version scope, unit `[role,sheet,recordId]` and field `[heading,form]` remain authoritative. A decision includes state, stable action ID and the accepted source hash; no English or parsed source catalog is added to SQLite. Existing source hashing stays unchanged, including its recognized `[NOAUDIO]` normalization. Other actual hash changes suspend approval rather than transferring it heuristically.

Shared publication inherits from the latest verified matching predecessor. Source changes set `needs_review`. New nonblank upstream targets are retained with an explicit conflict; they are never automatically cleared by an old decision. Revocation tombstones survive carry. Returning to an older source does not reactivate a suspended decision. Removed/renamed/mismatched units do not receive guessed decisions. Existing destination work and historical collections stay independent.

For a new local version, select **Carry Use English decisions from a saved local workbook** in Local workbooks before Open. It must match account, game, branch and language. The current files supply translations; only explicit decisions carry, with predecessor revision/history. Without this choice, importing identical names/bytes still creates independent work. It cannot be combined with separate previous comparison files. Revoking an older workspace after creating a successor does not rewrite the successor.

## Persistence, access and compatibility

Decisions use `clienttext-use-english-v1` and live in versioned authored records, existing shared provenance/history/events/receipts and collection cutoffs. Shared `saved:false` metadata-only decisions appear in the existing `sourceReviews` projection; clearing a nonblank target is authored Saved work. Marking an unchanged blank does not manufacture Saved. New commands carry `intentProtocol` and explicit `englishActions`; current ordinary saves carry the protocol so a nonblank save can revoke safely. Exact old receipt bodies remain unchanged.

The API advertises `clientTextEnglishIntent` and `clientTextEnglishEligibility`. Controls for shared work require both capabilities. New actions include a sparse `englishEligibility` witness with protocol `clienttext-english-eligibility-v1` and `{sourceHash,eligible}` for each acted-on field. The client derives it from its verified file; the API rejects missing, stale or false eligibility for Set and retains the sparse witness with the decision. This extends the existing trusted-client fact boundary: a hash cannot independently prove DNT content to the API, and a dishonest true witness is not cryptographically detectable without the file. No parsed source catalog is added; submitted previous editor text remains authored history. Legacy unsupported active events are preserved as `needs_review` rather than blocking the event cursor; revocation remains possible.

Existing role/language checks, CAS and idempotency remain. Old commands cannot modify an intent-bearing unit without the capability protocol; already committed receipts still replay with current access checks. Local Save commits values, decision, history, draft consumption and receipt atomically. Local decisions/previous editor values never enter Dictionary/TM resource transport or model requests. No conversion implicitly accepts or dismisses MTL.

## Shared conflicts and rejected commands

Competing approvals, including identical blank approvals, offer **Accept shared version** and **Reapply retained work and save ID**. Accept uses the latest accepted peer state and retains the private draft. Reapply creates a fresh command against the accepted revision, with current protocol and eligibility; the full old pending chain and previous editor values remain in local recovery history. The history panel exposes that archived evidence in collapsed details. Neither path silently modifies or discards an old command.

Definitive HTTP 400/422 validation rejections, including `INVALID_REQUEST`, `CLIENTTEXT_INTENT_REQUIRED` and `CLIENTTEXT_INTENT_ELIGIBILITY_REQUIRED`, retain the exact sent body and stop automatic retry. A newer ordinary Save must first resolve that retained operation explicitly. An uncertain response still retries its exact command and ID to find the existing receipt before recovery can consume it. Stable recovery jobs also retry their receipt after a lost acknowledgement. If a newer peer version overtakes an uncertain predecessor's receipt, every successor pauses for explicit accept or reapply, including ordinary translation commands. Further pulls cannot re-arm it or clear its unresolved conflicts. Private recovery archives stay in this browser; they are not uploaded as new shared history.

API **schema 30** is a semantic writer fence using existing payload storage; it adds no source table and rewrites no existing content. Stop all older API writers before starting the upgrade, including the earlier unapproved schema-30 review build; do not mix old and new processes against one database. Earlier schema-29 binaries must not reopen the upgraded database. Deploy the compatible API first and verify both capabilities, retain a pre-upgrade backup plus required original/collection artifacts, then deploy the frontend and reload old pages/workers. No production migration or deployment was run during development.

Browser **IndexedDB 25** fences older pages/workers while retaining all stores and pending bodies. New private workspaces/backups use **clienttext-local-v2**. The new editor reads legacy durable v1 workspaces/backups; marking an existing v1 workspace promotes its local protocol in the same transaction. Older v1 restore software rejects v2 archives rather than losing decision metadata. Backup/restore preserves decisions, tombstones, authored previous values and exact original packages, creating fresh workspace IDs as before. Do not clear storage.

## Validation and remaining choices

Focused synthetic regressions cover no inference, text-only eligibility, exact offers, source changes/reversion, Normal/Gender identity separation, upstream conflicts, CAS/receipts/access, local transaction abort, predecessor selection, raw count compatibility, immutable collections and resource isolation. The native `clienttext-local-browser-check.cjs --use-english-only` path uses the supplied PoE2 Thai workbook read-only for actual pointer conversion, ordinary identical Save, history, blank export, naming/palette, reload, backup/restore and revocation. The broader local fixture covers the supplied PoE1 original, DNT, ownership and crash/recovery boundaries. No live inference is needed.

Actionable Missing/progress is authorized by the owner follow-up and is implemented as a derived projection with no data migration. Bulk creation of explicit Eng decisions remains a separate product choice; independently verify runtime fallback for any additional forms/languages/game modes before widening eligibility. This change does not claim game-runtime verification, hosted OAuth/deployment, real disk failure or actual quota exhaustion. Review the API semantic fence, retained retry bodies and shared conflict behavior before publishing.
