# Use English placeholder and preview

Local change on `feat/eng-placeholder-preview`, based on freshly fetched origin/master `06874fb6cfa7815d422e481025a4d6aa67f74c8a`. Independent review precedes the parent's coordinated publication. This task performs no push or deployment.

## Behavior and boundaries

Valid active source-bound Use English fields show the exact dimmed placeholder `-- Use English --` in full and inline translation controls. Collapsed table rows show the same cue per approved field. The color uses the existing theme's muted text token. Empty controls use their native placeholder; whitespace-only raw values use the existing noninteractive highlight overlay because a native placeholder does not paint over whitespace. The raw value and selection are retained.

The subsequent [cue styling follow-up](clienttext_english_placeholder_style.md) reduces only its opacity to sit closer to existing placeholder text, with theme/contrast evidence and before/after screenshots.

The regular translation preview renders the field's English source through the existing game renderer when the current value is blank/whitespace and its approval remains valid. Keyword sheets, floating keyword windows and skill cards apply the same valid-decision rule. Variables, keybinds, keywords, formatting and possessive preview variants continue through their existing renderers. A nonempty editor draft takes precedence over the preview fallback. Frozen keyword windows retain their opening snapshot, as before.

The placeholder is presentation only. `ctValues`, field descriptors' translation values, formatting adapters, search/sort text, saved targets, checkpoints, history, retry bodies and workbook exports never receive it. An approved empty target still exports empty; approved whitespace keeps its exact raw whitespace. Rendering English does not manufacture a translation or change counters, assignment denominators, status colors, review, or export semantics. Ordinary SD fields and ineligible ClientText forms/Gender/DNT/PoE1 keep their existing behavior.

Existing Eng activation remains enabled for blank or exactly identical-English drafts and disabled for a different nonempty draft. Existing active approvals remain removable after typing a different draft. Revocation, changed sources, pending recovery, conflicts and ineligibility remove the resolved cue/fallback through the existing decision predicate. No eligibility, permission, toggling or persistence logic changes.

Product edits are limited to `public/editorSession.js`, `public/clientTextUi.js`, `public/clientTextSkillCards.js`, `public/keywordPopups.js`, `public/index.html` and one muted-color rule in `public/client-text.css`. No Lookup, shared Tooltip, source catalog, API, storage schema or migration changes. API remains `3e535402da908ba9a1506710ee38f642fa506127`; IDB25 / API schema30 / intent protocolv2 remain compatible.
