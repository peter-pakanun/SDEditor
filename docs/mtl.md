# ClientText MTL

MTL generates a suggestion for one ClientText text or grammatical-form field. Gender metadata and empty English fields are excluded. The field toolbar uses a compact square translation icon, immediately before the history separator. **Settings → MTL** contains the personal data-sharing choice and optional F8 or Ctrl+Alt+F8 shortcut; shortcuts are disabled initially. Admins also see the existing connection controls and limits panel in this section. Switching sections or closing and reopening Settings preserves unsaved quota edits; only **Save limits** applies them. Editor behavior and other keyboard shortcuts remain under **Editor & shortcuts**.

Translate, MTL review controls and **Settings → MTL** are visible to signed-in Translators and Managers with an assigned account language, and always to Admins. The selected editor language does not count as an assignment. Assigned Managers and Admins retain their existing all-language access; a Translator selecting another language still sees the disabled Translate control. Losing an assignment hides MTL without discarding ordinary drafts or separate review buffers. Shared character tone notes and other private assets keep their existing access policy.

Generation uses a separately configured external translation service. Settings ask permission to transmit the selected English field and bounded relevant workbook context, Developer notes, saved character tone notes and selected Dictionary glossary terms, and privately retain generation evidence on the app's server. Consent version `mtl-v2` explicitly covers retained source, executed prompt and context even for local workbooks, plus the original generated output and any edited rejection on explicit Dismiss. Previous `mtl-v1` consent is preserved as historical settings data and requires a new explicit choice before new generation. Existing admitted requests retain their original identity and recover without inference replay. APIs without advertised review-archive support show upgrade guidance for new generation and dismissal; existing work and acceptance remain available.

Generation needs a network connection in every editing mode. Local workbook persistence does not make model generation available offline. A cached online workspace retains its online identity while disconnected.

Context keeps directly referenced keyword IDs, English definitions and whole trusted Saved/original translations first, before notes, references, glossary or surrounding examples. Keyword definitions keep their existing field and size limits; useful definitions are not shortened to make room for examples. If a keyword cannot fit the hard request bounds, diagnostics report its omission. Main and alternate Dictionary definitions match the selected English or its direct keyword definitions, rather than unrelated referenced biographies. Each matching definition contributes its own source and translation; an unmatched or blank main definition does not suppress a matching alternate. Alternates inherit the parent game scope and current-game shadowing, and retain the existing phrase boundaries and context limits.

For KeywordPopups/KeywordPopups_Gender **Info Title**, the initial packet also includes that exact loaded row's title and same-form English Info Content, when present, plus a valid current Saved/original target title. The two-field projection uses existing role, workbook/language snapshot, freshness, conflict and size guards; drafts and provisional MTL never enter context. Oversized records or target text are omitted whole. This needs no additional model call. Prompt v8 explicitly treats Info Title as display text even when it equals immutable recordId; protected link IDs remain unchanged. Missing definitions supply no facts.

At most two surrounding records are selected from the loaded immutable workbooks, independently of editor filters. Non-dialogue examples require the same worksheet and record role, matching field name/group and kind (and exact grammatical form), and a trusted translation that passes the existing MTL protected-token, variable, syntax and line-break validator against its own English. Rank is lexicographic: distinct shared protected keyword IDs, exact nonblank metadata matches, then normalized text similarity. Similarity uses NFKC, lowercase, punctuation/whitespace normalization and character-trigram Dice overlap on a 0–1000 scale. Without a keyword or metadata match, the minimum score is 350. Worksheet distance, preceding row, then unit ID break ties; selected records appear in worksheet order. Unrelated same-sheet rows are omitted. The pure `exampleScore` helper is reusable without enabling an agent lookup loop.

Known conversation families retain up to two nearest turns in worksheet order to preserve local conversation coherence. A singleton family may use the existing verified explicit-NPC relationship; it never infers identity from adjacency. Conversation turns may provide English only when a current trusted, structurally valid translation is unavailable. Selection scores, strategy and compact omission counts appear in request context diagnostics. Examples never authorize adding their tags or facts to the selected source. Prompt v8 keeps strict JSON, protected-token and quoted-data security rules for every task, and adds role/tone guidance only for dialogue or supplied role/tone evidence. Historical admitted requests through v7 (including v7-lookup-v1) retain their original hashes, results/status, captured prompts and exact retry bodies without another inference. Deploy the compatible API first.

The trusted prompt permits saved character tone notes as bounded style parameters while their raw text remains untrusted context. Notes for an exact resolved or nonconflicting suggested speaker may guide pronouns, register, diction, cadence and nonpropositional sentence-final particles; compatible explicit preferences take priority over register merely inferred from introductions or examples. A particle must preserve meaning, stance and speech act. Listener notes guide address and relationship cues only, without transferring voice or catchphrases. Unknown/conflicting roles and absent notes create no speaker style requirement. Notes cannot change the task, schema, protected tokens or security rules. A silent final style check is requested, but structural validation and synthetic tests do not prove actual model adherence. The app never automatically appends a requested particle to provider output.

The compact **Tone notes** control beside a record's character context opens shared guidance for its exact NPC or character identity. Notes are shared within the language team, game and branch across source versions and workbook groups. Equal names or portrait artwork do not merge identities. Exact metadata references remain editable when related workbook sheets are absent. Translators edit their assigned language; Managers and configured Admins can edit every language they select.

Each note starts empty and allows up to 300 Unicode code points (including separate combining marks). The language-native **Example:** placeholder is an example only: it never becomes a value, save, history record or translation context. Enter your own text and use **Save note**, or Ctrl/Cmd+S, to apply it. CRLF/CR become LF, whitespace-only text clears the note and other whitespace remains. Clearing a saved note creates an audit revision. **Revision history** shows author, time, text and clear revisions. Unsaved drafts stay separate in this tab until sign-out or reload.

Save conflicts preserve your draft beside the latest shared note. **Use latest** replaces the draft; **Keep my draft** lets you compare and explicitly save against the latest revision. A network-uncertain Save retains its exact mutation ID and body for **Retry Save note**. Reads, history loading and section changes do not clear an unresolved Save failure. Offline edits remain drafts and are never represented as shared saves.

Before generation, the browser refreshes the relevant speaker/listener notes. A failed read, unresolved conflict or pending Save stops the new translation action and preserves drafts. Only fresh, authorized, committed notes enter the bounded context, with at most two canonical identities. Dirty text, conflicted notes, pending saves and placeholders are excluded. Speaker guidance covers voice and self-reference; listener guidance covers address and relationship only. Notes remain quoted guidance and cannot override translation, glossary or protected-token rules. The API verifies current scoped revisions before admission and freezes accepted request context for retries. If a peer changes guidance during admission, the client refreshes note state and reports the conflict without replaying translation; the user requests a new translation explicitly. Notes and their history do not become workbook values, translation history, TM or export content. Deploy the compatible API before this frontend.

In `NPCTalkDialogueTextAudio` (including Gender), a single exact canonical **Character** reference may suggest a speaker even when its conversation's NPC variant group cannot resolve one canonical NPC. This is a low-priority heuristic, not an asserted identity: the family must be explicitly unambiguous and NPC grouping must be the only order blocker. Explicit roles, filters, extra actor references, conflicting groups, and identity-bearing or unknown suffixes exclude this fallback. Absent, `NoLore` and `HasLore` suffixes are allowed as conditions, never listener IDs. Ordering stays suppressed with every reason retained, and the listener remains unknown. Only the supplied tentative speaker can contribute a fresh saved note; an NPC name, shared portrait or audio filename never selects a listener note.

While generating, the field is read-only and a subtle glowing skeleton covers its original text. Incoming provisional text replaces the skeleton directly in the field; it stays separate from the native draft, candidates, history, TM and exports. Reduced-motion settings disable the glow. Click the spinning Translate button, or focus it and press Enter or Space, to stop. The original draft reappears immediately; editing resumes when the request ends. An unconfirmed stop leaves an actionable warning and continues checking the same request. A completed result that wins a stop race stays behind explicit Review.

Admins can view nonsecret connection status and disconnect or revoke the server session in Settings. Changing that connection requires an Admin sign-in from the last five minutes. Setup uses a dedicated local SDEditor sign-in followed by a protected server import; no hosted one-click connection is offered. Renewable credentials live in a separate encrypted backend database, with its encryption key stored outside that database and excluded from content backups.

All MTL controls, connection guidance and errors use neutral wording. The **MTL data sharing and privacy** details beside consent explain which context is sent to an external translation service, the applicable account/service terms and the human review requirement. The prior saved or original translation remains in use until explicit acceptance and Save.

An Admin-only information button next to Translate opens a movable, read-only request dialog. Before translation it shows a clearly labeled context preview without making an inference request. The preview and each new request use a detached snapshot of the live selected Dictionary, including unsent edits. An open unsent preview refreshes after Dictionary edits; submitted request context, copied JSON and downloaded records remain the exact captured snapshot. After translation, **Prompt and context** shows selected fields from the actual executed prompt, bounded context, response, structural validation, timing and safe error codes. Connection configuration is omitted. Quoted workbook, prompt and response text remains accurate. When supported by the API, the request section includes bounded extra-context lookup rounds, sanitized executed calls and their wait timings. Drag the header or focus it and use arrow keys to move the dialog. Escape closes it and returns focus to the button.

Server diagnostics are captured only for an Admin's own request, checked against current Admin authorization, original workspace/language permissions and the same signed-in session. They stay in bounded process memory for up to ten minutes and never enter candidates, history, backups or logs. Browser details clear on logout or account, language, workspace, source or selected-record changes. Text is escaped and credential-like values are redacted; transport headers, credentials, raw provider errors and reasoning are excluded. Opening or reopening the dialog does not consume translation quota or invoke the provider. Expired details cannot be reconstructed from durable work.

Prompt and Context have separate copy icons. Each copies the complete displayed, sanitized section as readable JSON. A successful copy briefly says **Copied**. If automatic copying fails, the section is selected for manual Ctrl+C and a clear failure message appears.

## Review and Save

A completed suggestion replaces the visible field as a cyan-accented MTL review overlay. The original or Saved translation and any ordinary draft remain underneath it. Typing, pasting, formatting, autocomplete and TM insertion in the overlay edit a separate review buffer. They do not mark the source reviewed, create Saved work, teach TM or change export data.

**Accept** copies the reviewed suggestion into the ordinary draft and acknowledges the exact current source. Apply it with normal **Save**. Before Save, the prior draft is retained for undo/recovery. Save records normal translation history and MTL provenance and resolves the selected candidate atomically. An unchanged explicit save remains allowed. Normal human edits after acceptance retain ClientText's support for intentionally blank fields.

**Dismiss** resolves the selected unaccepted candidate and restores the underlying draft or committed field without marking the source reviewed. It queues a private server review archive containing the retained generation evidence, original generated text and separately recorded edited rejection, if any. Editing a suggestion never replaces its original output. Repeated clicks cannot create another dismissal command. Saving while a suggestion is unaccepted saves only the underlying ordinary draft. It does not accept the visible MTL suggestion.

New dismissals, including rejection of a legacy suggestion, require the explicit updated retention choice. The client checks consent before staging and again across asynchronous storage guards, and includes `consentVersion: 'mtl-v2'` in the new command. Withdrawing consent blocks new commands; an already authorized outbox command retains its original body and mutation ID for exact retry without implying renewed consent.

An archive is confirmed only by a valid `sdeditor-mtl-dismissal-v1` receipt with `status: saved`. HTTP 503 `MTL_REVIEW_ARCHIVE_PENDING` means the dismissal and archive payload committed but the file is still pending; the UI reports that state and retries the exact original mutation ID and body, including after a lost acknowledgement or server restart. A pending dismissal prevents generation for that field until its receipt arrives. Account, language and workspace guards fence callbacks and reconnect attempts. Failed retries remain visible until the relevant operation succeeds; healthy background retries are silent.

Shared dismissal requests use the existing durable scoped outbox. Local dismissals use `/v1/mtl/local/requests/:requestId/dismissals`; durable local workbooks retain their scoped candidate/review/outbox records in this browser. Offline requests wait for authenticated reconnection under the existing access and exact-request guards. Older memory-only tabs still lose unsent local dismissals when closed or refreshed. Evidence already received by the server is retained privately under `DATA_DIR/mtl-review/dismissed/` when explicitly dismissed. The archive has no translation-export or TM role. Acceptance, expiry, supersession and stale-source hiding do not request a dismissal archive.

Translate and review actions preserve the inline editor, selected record and ordinary draft. Pointer translation keeps focus in the field; keyboard translation moves focus to the stable toolbar wrapper before its button is disabled. The field stays mounted when a suggestion arrives or is accepted/dismissed. Request-details dialogs participate in the editor's focus surfaces.

The MTL count and field dots appear only when applicable unresolved candidates exist. Counts overlap existing content statuses and do not contribute to Saved/Revised or assignment progress. The MTL filter and attention navigation provide access to pending suggestions, including suggestions withheld because newer typing arrived during generation.

## Scope, lifetime and export

Online candidates and their lifecycle synchronize separately by content group, version, language, unit and field. Personal review edits stay in their own account-scoped browser store. One contributor's review buffer is not overwritten by another contributor's save, dismissal or regeneration. Conflicts require a fresh review.

Local workbooks retain candidates, review buffers, committed translations and drafts in their private browser scope. Workbook exports include committed translations only. Recovery backup restores workbook values/history/drafts and originals, but does not recreate model request state or accept old MTL claims in a new scope. See [local workbook recovery](clienttext_local_workbooks.md).

Every suggestion binds to the immutable original, parser, exact field source and its raw content hash. Source changes silently make the suggestion inapplicable; candidates are not carried into another version. Pending results cannot replace newer edits or enter a different account, language or workspace.

Exports read ordinary Saved records and verified original workbook cells. Unaccepted suggestions and review-buffer edits are excluded from all exports and collections. Accepted but unsaved drafts are also excluded. Existing complete paired-workbook export requirements remain; absent optional context sheets do not invent context or create sheets.

## Host limits

The host reserves usage atomically before inference. Defaults are one active job per account, two across the process, five new jobs per minute per account, 50 per day and 250 per week per account, and 100 per day and 500 per week for the configured subscription. Day and Monday-start week boundaries use `Asia/Bangkok`. Identical retries count as the same job. Provider rounds are counted separately and capped at three. Source/context/output size and elapsed-time limits are also enforced.

With lookup v1 support, Translate can request up to two rounds of additional exact keyword or record context from the loaded workbook. One round allows two queries and four records, independent of the editor filter, with whole current original or approved Saved translations where valid. No workbook is parsed or uploaded by the lookup API. Missing sheets provide no invented context. Retrieved text remains untrusted evidence and cannot replace the original role hints, tone notes or glossary priority. The skeleton/stream and Stop control remain in place; a short tooltip identifies the retrieval phase.

The counts are explicit: no lookup takes one provider call; one lookup round takes two; two lookup rounds take three. The last call must translate. All calls and waits use one original job reservation, its concurrency slot and the original deadline of at most 180 seconds. Serialized requests reserve at most 64 KiB per call/192 KiB total. Local observation stops on visible-output JSON/text exceeding 128 KiB per call/256 KiB total, or received SSE data crossing 1 MiB per call/3 MiB total. These are byte limits, not model-token spending caps; SIWC does not support an output-token limit, and the app does not measure or hard-cap hidden reasoning or provider computation. A crossing observation is counted and aborts locally; upstream cancellation is best effort. Lookup results add at most 16 KiB/8,000 characters, within a combined context cap of 56 KiB/24,000 characters. A challenge and a disconnected browser lease each expire within 15 seconds. No provider call is automatically retried. See [the lookup contract and rollout checks](mtl_context_lookup.md).

Admins can expand **MTL limits and usage** in **Settings → MTL** to edit the seven request and concurrency limits. Values change only after explicit **Save limits**. Server-counted usage is shown as used/current limit, with rolling-minute releases, calendar reset times and active/max concurrency. Per-user usage belongs to the signed-in Admin; connection totals include all accounts using the configured connection, and server concurrency includes all accounts. The panel refreshes every five seconds while expanded in the visible MTL section and preserves unsaved edits. Leaving the section or closing Settings stops polling; returning resumes it. Saving limits does not reset counters or cancel active requests. Conflicts preserve the Admin's edits beside current server limits; an uncertain Save retries its original body and mutation ID. Older APIs show an unsupported message.

Uncertain requests retain their identity for recovery. Checking a request or replaying a save receipt does not request another generation. A failed or interrupted job does not automatically start another provider call.

If a proxy masks a failed translation response as a network error, the browser reads the same request's status once. A confirmed validation failure gets a neutral MTL explanation; an unavailable status keeps the original request recoverable. This does not repeat inference. Admin details include the upstream HTTP status when received, a separate API error status, and a bounded validation reason without raw upstream errors or response payloads.

Completed translation output rejected by JSON/schema or application validation returns HTTP **422**. Genuine upstream protocol/transport failures retain **502**. The default connection requires an actual `response.completed` event, a completed response with the expected message structure and consistent streamed/final text. Cloudflare requires a verified assistant choice, a successful `stop` finish and `[DONE]`; empty terminal/usage chunks are allowed while extra visible output remains rejected. Every provider still requires strict translation JSON and all protected-token, audio-marker, syntax and line-break checks. Partial text never becomes a suggestion.

Admin diagnostics use fixed reason codes: `stream_content_type`, `stream_json`, `stream_incomplete`, `response_shape`, `delta_mismatch`, `output_json`, `output_schema`, `protected_tokens`, `line_breaks` and `text_syntax`. Additional fixed reasons distinguish stream limits/read failures, audio markers, refusals and HTTP/transport failures. For example, `upstreamStatus: 200`, `apiStatus: 422`, `failureReason: protected_tokens` means the upstream request completed but the returned translation changed protected tokens. A protocol failure can still be inspected through the Admin diagnostics GET after a proxy masks its failed POST, without another inference request. Old jobs and expired diagnostics retain only their historical error code; that code cannot retrospectively establish the precise cause.

Admins can expand **Timings (ms)** in **MTL request details** to inspect browser preparation, fresh note reads, the admission POST round trip, observed provider milestones, validation and completion. Browser and API monotonic clocks stay independent; overlapping durations are not a breakdown to sum. Provider observations include transport and service time and cannot distinguish queue from reasoning. The first provisional text frame uses a DOM update plus animation-frame callback, not proof of screen paint. Missing, expired, hidden-tab or older-API measurements show **Unavailable**. Timings remain bounded session-local diagnostics and never enter translation history or exports.

Cloudflare request details retain a bounded trail of terminal, trailing and rejected stream chunks. **Download all** includes it as `stream-chunks.json` when available, also inside the request's stream summary, even when `response.json` is `null` because completion failed. The trail shows whether `stop` and `[DONE]` were seen, the accepted-trailer count, event phase/disposition, choice indexes/finish reasons and up to 1,024 characters of visible content per choice. Optional fixed type labels for the delta/content and flags for audio or unknown delta/choice fields distinguish unsupported output from an empty trailer without retaining unknown field names or values. It keeps at most six chunks and two choices per chunk, with omission/truncation markers. Hidden reasoning, tool/refusal payloads, provider errors, arbitrary fields, transport headers, credentials and raw response IDs are excluded; known secret-shaped text is redacted. These are session-local Admin diagnostics, not translation/export values or server review archives. Older debug snapshots cannot recover a chunk they did not record.


## Admin model settings

A gear beside Translate opens a model-settings bar for the configured Admin. It applies only to that Admin's next requests in the current sign-in. The default is **Sol / medium** for every role. Existing explicit Admin choices remain in effect until changed or reset. **Use default** removes the override. Opening the bar checks the connected account's available models; unavailable metadata leaves an actionable message. Account, client, role and assignment changes clear or fence choices.

Allowed choices are GPT-6.1 Sol at low/medium/high/xhigh/max, GPT-6 Luna at none/low/medium/high/xhigh/max, intersected with account availability, and **DeepSeek V4.1 Flash (1017) · Cloudflare** at none/low/high/max for Admin testing. The Cloudflare model ID is `@cf/deepseek-ai/deepseek-v4.1-flash-1017`. Switching from an unsupported effort such as medium selects high. Translate captures the choice before context preparation; later changes do not alter running requests, retries or review evidence. Managers and Translators have no model-setting controls or override permission. Nothing changes ordinary review, Save, source validation or exported translations.

Cloudflare uses its own server credentials and billing. Set `MTL_CLOUDFLARE_ACCOUNT_ID` and `MTL_CLOUDFLARE_API_TOKEN` in the API's private runtime environment with `MTL_ENABLED=1`; keep the existing `MTL_PROVIDER=siwc` default. No Cloudflare token is entered or stored in the browser. Without those credentials, its choice remains visible but disabled with setup guidance. A configured Cloudflare connection is independently usable even when the default translation session is disconnected. Selecting it sends the same bounded source/context and glossary through Cloudflare's OpenAI-compatible chat endpoint, with the existing output, protected-token, review and Save guards. There is no automatic provider fallback and **Use default** returns to Sol/medium. See the [Cloudflare model documentation](https://developers.cloudflare.com/workers-ai/models/deepseek-v4.1-flash-1017/) for its current paid access requirements.

Fast stays disabled: the documented Sign in with ChatGPT account catalog does not establish Fast support or entitlement for this connection, and the Cloudflare test choice does not offer Fast. Lower reasoning effort is a separate choice and does not enable Fast. The server rejects speculative fast/tier fields, sampling and token-limit overrides. The translation output schema and safety bounds remain fixed. API model names and reasoning levels are visible only in this explicit Admin configuration surface and request metadata. There is no hosted credential entry or model probe by inference. Deploy the compatible API before this frontend.
