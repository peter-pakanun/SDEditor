# ClientText reference portraits

Inline and full ClientText editors show reference artwork beneath the first English source field and its audio controls, whether the English game preview is visible or hidden. Portraits do not reserve space in the preview; its height, independent scrolling and resize control remain separate. The leftmost contextual NPC appears first, followed by distinct explicit Character and NPC references. Context is not a claim about the actual speaker; Character Filter is a listener constraint.

The public frontend contains only identifier mappings and display code. It contains no portrait images, encoded image payloads or image-source URLs. The portrait catalog is generated from the reviewed installed-client tables and sprites. Exact NPCs.Id joins through Portrait and NPCPortraits.PortraitFile to the sprite. Exact game-specific paths and forms stay primary. Unmapped references may fall back to their resolved English NPC name, normalized only for case and whitespace, when that name has one canonical portrait or an explicit reviewed default. The Hooded One defaults to the normal portrait; an exact night-form path still selects the night artwork. Other ambiguous names stay unresolved. Repeated canonical portraits merge their path evidence, and a resolved NPC card suppresses its duplicate group placeholder. Known NPCTextAudio portrait overrides require the exact record and matching explicit NPC metadata.

Character metadata resolves through the built-in exact-path catalog even when the workbook has no Characters sheet. In PoE2, Metadata/Characters/Int/IntFour is Witch and Metadata/Characters/Int/IntFourb is Sorceress. Both icon sizes resolve to their preferred 900x866 full portraits. All twelve known PoE2 Character paths are included. Marauder, Duelist, Shadow and Templar use the user-approved provisional 629x579 sources, with an asterisk and explanatory tooltip; review them at PoE2 1.0. No released portrait is asserted for these four. PoE1 metadata uses its own exact paths and available source mappings.

Metadata context and lookup labels use the same canonical Character catalog when an exact supported path cannot be resolved from the workbook. Ascendancy Filter and Prohibited Ascendancy Filter also use verified exact PoE2 Ascendancy Id/Name pairs from the installed client; Witch3 is Lich and Witch3b is Abyssal Lich. DNT-UNUSED entries have no static friendly fallback. Resolved workbook English stays primary. Fallback tooltips retain the full identity and identify the static game-specific mapping; raw metadata, unknown IDs and other reference handling remain intact. Variant and filter metadata adds no portraits.

Class-variant controls use that same Character catalog for their short worksheet form IDs when the Characters sheet cannot supply a resolved English name. IntFour and IntFourb therefore display Witch and Sorceress in both metadata and variant controls. Resolved workbook names stay primary; disabling class-name mapping or encountering an unknown form keeps the raw ID. Labels never rewrite worksheet identities, saved text or exports.

NPC forms retain their source mapping: Doryani's helmet portrait is distinct from Doryani, and Hooded One night lighting is distinct from the normal form. RavenBoy and RavenBoyHub map to ChildTangmazu. StrangeVoice has no exact portrait mapping; when its workbook-resolved name is The Raven, the requested unique-name fallback can use the Raven portrait. Unidentified raw paths cannot invent a name. All three LoyalCompanion/Squire records have null Portrait and remain named placeholders because no verified portrait name is available. Objects and Info references are excluded from NPC artwork assignment. Unsupported or ambiguous identities retain placeholders.

The API serves GET/HEAD /portraits/<poe1|poe2>/<id>.webp?v=4. It only reads reviewed, bounded, digest-verified local WebP files; no request fetches an upstream URL. The private API repository packages the runtime manifest, provenance and prepared images in assets/portraits, so its normal git-pull redeploy includes the artwork. Raw PNG/DDS originals and earlier source research remain in ignored API data storage. Bearer-only media requests support frontend-first deployment; an old/missing API image does not prevent local editing.

The current API requires a current authorized cloud session and stored assignment. The shared private-media adapter checks the selected language locally, fetches language-neutral bytes with the bearer header, then gives the image element a validated Blob URL. It omits the optional language header to remain compatible with the previous API's CORS policy. It never puts credentials in URLs. Signed-out or denied sessions retain named placeholders. Scope/access changes revoke URLs; replacement/unmount abort pending loads. Images are not persisted for offline use. See [contextual skill cards](clienttext_skill_cards.md) for the shared loader contract, rollout behavior and authenticated browser/API checks.

Images use a transparent 320x360 prepared canvas displayed at up to 160x180 CSS pixels, preserving source aspect ratio and alpha. Two fit side by side where space permits. Larger groups overlap within the English column, with the leftmost on top; hover/focus expands them and Escape collapses them. Authorized fetches use `no-store`; native images decode the resulting Blob asynchronously. Failed images show named placeholders and retry after connectivity returns.

The reviewed package has 143 preferred image entries: 35 PoE1 and 108 PoE2, including variants and non-character sprite entries. These are not 143 distinct NPCs. The static catalog has 86 PoE1 and 416 PoE2 verified NPC paths, plus exact Character paths. The coverage script reports per-sheet counts, including exact-name fallbacks, and does not export authored translations. Coverage depends on the workbook's resolved English NPC identities; unknown and ambiguous names can still lack images. Identity/variant reference counts overlap.
