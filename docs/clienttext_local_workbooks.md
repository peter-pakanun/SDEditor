# Local ClientText workbooks

**Offline → Local workbooks** opens one language's XLSX/XLSM Normal workbook, Gender workbook, or pair. Give it a recognizable workspace name. Each import creates new private workspace/version IDs, even when names and bytes match. Use **Reopen local workbook** under Offline to continue earlier work; importing again does not replace it. Account, game, branch, language, version/group, role, sheet and record identities remain distinct. Signing in does not silently adopt guest work. Select the original account and game to find its workspace, or restore a downloaded backup into the current account as a new workspace.

The exact imported packages, committed values, source review hashes, history and private drafts are stored in IndexedDB on this browser origin/profile. Moving or deleting the selected disk files after a completed import does not affect these retained packages. Save still commits the whole ID and creates history; typing only checkpoints a draft. Drafts do not change committed statuses, history, progress or exported workbook cells. Blank ClientText fields remain legal. DNT visibility, field/form identities, source review, purple Revised/grey completion and native workbook export rules are unchanged.

The workspace banner distinguishes a pending checkpoint, a failed checkpoint, a stored draft and committed work. Local draft writes start on input and also flush before normal navigation, Save, export and visibility changes; recovery does not depend on beforeunload. The last input may still be pending when the browser process crashes. Only transaction completion confirms a checkpoint or Save. If storage fails, keep the tab open and use **Download current draft**. A forced account/language/context change retains a failed outgoing draft in this tab, with a scoped **Download unstored draft** action in Offline. Browser shutdown can still lose uncheckpointed text.

Opening, leaving, switching or closing an editor never deletes durable work. **Discard draft** requires confirmation and deletes only the selected ID's expected draft revision; committed text/history and other drafts remain. There is no automatic workspace deletion. A workspace already open in another tab cannot be opened for editing until that tab leaves/closes it. Web Locks support over HTTPS or localhost is required; unsupported browsers fail visibly rather than editing without ownership.

## Recovery and backup

After refresh or browser restart, choose the same account/game, open Versions → Offline, and **Reopen local workbook**. Select the Draft filter/ID to resume checkpointed text. A workbook cannot activate if its originals, identity or authored records are malformed; the browser records remain available for investigation rather than being cleared.

**Download workbooks** exports committed work using the retained original packages and `_Translated` names. Unsaved drafts and history are excluded. **Download recovery backup** produces a local ZIP with exact original workbook bytes, workspace metadata, saved work, drafts, history and receipt evidence. It also includes a selected previous comparison workbook. Save this ZIP outside the browser. The browser's download event only establishes initiation; verify the file exists and retain more than one backup when appropriate.

**Restore local recovery backup** in Offline validates the archive and exact workbook hashes, reparses with its recorded supported parser, validates authored fields/reviews, and creates fresh workspace/version IDs. It never replaces an existing workspace. Resource synchronization starts disabled on the restored copy. Existing receipt bodies/signatures are retained as historical evidence, without rewriting them into new commands. Restored MTL acceptance claims become inert draft recovery metadata; they do not accept a candidate in a new scope. Derived local TM and active model request state are not restored from the recovery archive. The original workspaces remain intact.

If a draft checkpoint fails but the backup can still read committed storage, the ZIP contains `uncheckpointed-editor.json` separately. These newest values need manual recovery; the normal restore action does not silently commit them. **Download current draft** and **Download unstored draft** are standalone JSON recovery copies for manual reconstruction, not workbook imports. A read/open failure can prevent the full backup; the current draft action remains available without IndexedDB. Restoring an interrupted backup again creates another independent copy. Incomplete restore records remain retained and are not listed as ready workspaces.

IndexedDB is local persistence, not cloud backup. Clearing site data, changing/losing the browser profile, private browsing cleanup, storage eviction, browser defects or device loss can remove it. Normal editing requires no network after the application and its dependencies have loaded, but a first offline page load without cached application/CDN files is not guaranteed: this feature does not add a service worker or offline application installer. A different host, scheme or port is a different browser origin and cannot see the first origin's workspaces.

## Boundaries and implementation

Workbook work has no upload, collaboration room, server synchronization or server source storage. **Sync Dictionary and TM** remains an independent, initially unchecked choice with existing assigned-language/Manager/Admin access checks. Only eligible Dictionary/TM resources use their established account stores and retry queues. Drafts, workbook packages, committed unit records, review/history and private workspace identities do not enter that resource transport. Without opt-in, Dictionary changes stay temporary and learned workbook TM uses the exact private workbook scope. Existing explicit MTL consent/access/network requirements remain separate; opening/recovering a workbook never requests inference.

`ClientTextLocalStore` uses `ClientTextStore` and its existing trusted-original cache, scoped records and native transactions. Originals prepare in bounded cache batches. The ready workspace pointer is published after those caches complete; optional previous-source comparison saved overlays, required-review provenance and history publish in that same readiness transaction. Save atomically commits saved work, local TM, history, expected draft deletion and idempotency receipt. An uncertain response can replay the exact job ID/body without duplicate history or consuming a newer draft. Local groups suppress the workbook outbox at the durable boundary and reject shared apply/acknowledgement operations.

Web Locks hold exclusive ownership for an entire editing activation. Mutations check ownership again through the transaction guard. Delayed outgoing draft writes retain their captured scope/lock until settled; old release callbacks cannot release a newly acquired scope. The lock is released when the page leaves or closes, including browser process termination. Existing revision checks remain additional protection. Read-only original/history access can inspect a comparison scope without opening another editor.

The database upgrades from `sdeditor` v23 to v24 to fence older pages/workers. All existing stores, authored state, migration journals, receipts and old pending request bodies remain. Existing normalized/legacy conversions keep their prior resumable contracts. No storage clear, server/API schema change or production migration is needed. The private content protocol is `clienttext-local-v1`; `local:test:*` remains the reserved private namespace for compatibility with existing resource/comment/access guards. Backup restore readiness is a separate commit marker. Future field/form/source disposition metadata belongs in versioned private records and must remain outside resource sync; this feature implements no Use English policy.

## Older temporary tabs

Already-open older releases continue running their old memory-only code. Updating the site does not turn those tabs durable. Before closing one, follow [temporary-session recovery](clienttext_memory_recovery.md) and verify its downloads. A memory-only tab already refreshed or closed cannot be reconstructed from IndexedDB because it never stored the workbook there. Dummy `?testMode=1` SD fixtures remain memory-only and do not establish persistence behavior.

See [local workbook validation](clienttext_local_validation.md) for the exact reviewed base, commands, evidence and tested limits.
